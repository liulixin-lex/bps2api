## 2. 项目背景与目标

项目从 sub2api 部署与维护演进为独立的 bps2api 分支，用于代理 BPS 并兼容现有客户端协议。
用户的持续目标是大量用户、并发请求和大量图片下接近原生 Codex 的使用体验，同时减少网关兼容错误。
历史故障包括间歇性 503、图片容量误拒、BPS 开关保存后变化、工具源码传输错误、未知历史内容和错误上游路由。
最终路由要求明确为：只有选中的 OpenAI OAuth 账号开启 Excel/BPS 时走 BPS，其他供应商保持原通道。
“减少错误”不等于消除上游授权、限流、容量不足或尚未支持的能力，也不能据此宣称仓库无缺陷。

## 4. 必须保留的决策与旧行为替代

### 4.1 路由、开关与暂停

`openai_excel_bps` 按实际选中账号的 platform/type 生效：OpenAI OAuth，排除 shadow、agent identity 和 PAT。
其他供应商、OpenAI API-key 等不因保留同名 extra 字段就转入 BPS；OpenAI 兼容 JSON 不代表 OpenAI 供应商。
v0.0.13 开启后不因工具、历史、参数或旧 `openai_excel_bps_models` 绕到原生；关闭后使用原生通道。
v0.0.4 的 forced-tool 原生回退、后续兼容分流是历史行为，现行路由以 v0.0.13 为准。
403 自动暂停需 opt-in，并保留开关；暂停账号不正常调度，直接进入 BPS 分支返回 `basispoints_routing_paused`。
单账号编辑保护最新数据库暂停状态，显式 `null` 表示恢复；批量明确提交 BPS 布尔值会清除暂停。
旧模型列表只保留为历史元数据。独立 Images API/alpha search 不支持时显式拒绝，不偷偷换通道。

### 4.2 工具与终态

FUNCTION、FUNCTION_CODE、CUSTOM 必须匹配实际工具目录，保留工具身份、源码字节、参数和历史。
网关负责传输适配，不在服务器执行客户端 OfficeJS 或 shell 源码；未知工具和模糊批次不能靠猜测执行。
安全的输出前恢复共享有限尝试次数与原始 deadline；已输出文本或派发工具后不自动重放。
真实权限、取消、限流和耗尽恢复预算的错误仍可见；incomplete 保留原始部分结果，不标成 completed。

### 4.3 图片与资源

`detail=original` 原样保留，不降到 high。已知图片别名可以规范化，冲突引用、非字符串 detail 和未知二进制仍可拒绝。
data URL 经有界中继转换；读取、解压、处理、图片存储、下载和等待容量有各自边界，默认值不代表生产生效值。
v0.0.1 未采纳随槽数隐式扩张预算的上游方案；提高并发必须基于目标主机与完整链路负载验证。
保留旧容器用于旧图片 token、在途流和回滚；只有图片 404 才查找下一实例，不等于主推理已负载均衡。

## 5. 三类历史事务必须分开

### 5.1 源码事务：保存了同输入对照

交接 JSON 保存 `TestStrictBPSRouteSwitch` 的同输入测试事件，范围为 BPS 开关 × Responses/Chat × 流/非流。

| 历史阶段 | 退出码 | 观察到的行为 |
| --- | --- | --- |
| BASELINE | 1 | 开启 BPS 时错误走原生；关闭 BPS 的原生分支通过。 |
| MODIFIED | 0 | 开启时走 BPS，关闭时保持原生，矩阵通过。 |
| 执行 ROLLBACK.sh | 0 | stdout 为 `Restored baseline source bytes`。 |
| ROLLBACK 后同一测试 | 1 | 恢复原来的开启 BPS 错路由；这是原行为恢复，不是回滚脚本失败。 |

历史四角色是 `MODIFIED_FILE.tar.gz`、`DIFF_FILE.patch`、`VERIFICATION.txt`、可执行 `ROLLBACK.sh`。
本轮检查其原绝对路径全部不存在；上传 evidence 的 `reopened:true` 属于旧环境，不是本机重新打开的证明。
本轮只读取历史事件，未再次执行整套源码替换、测试或回滚，也未补造缺失原件。

### 5.3 账号数据库事务：独立的状态改变

历史上，最后一个原生可调度账号因 OAuth 被撤销而失效，相关组失去可用账号并出现失败。
执行者直接将另一主要 BPS 账号恢复可调度；该修改作用于新旧实例共享数据库。
最后记录主要池依赖一个 concurrency=30 的 BPS 账号，属于容量与可用性单点，不是充足账号池。
名为 before 的调度快照实际在修改后生成，值已经为 true，不能当真实变更前备份。
其他账号集中不可调度的根因没有充分证据；不能写成已证实的人为或策略关闭。
这些是历史账号角色和状态，不能当作当前池现状；源码/部署 rollback 均不自动撤销账号字段。

## 6. 已有验证究竟覆盖什么

- 历史候选与公网标准 canary 为 4/4，协议 canary 为 5/5，实际入口是 Responses 和 Chat Completions。
- Messages 有源码/单元测试覆盖；这两套线上脚本未发送 `/v1/messages`，不能写成线上实测通过。
- Office 是合成 echo，验证本地 schema 的 `$ref`、source 和 label；没有真实 Excel/PowerPoint 宿主或工作簿写入。
- function-code 检查参数往返，未执行返回命令；25 张图片是重复红图，不证明逐张理解不同图片。
- 请求 ID、usage 关联、路由标识和 upstream_endpoint 比单看 HTTP 200 更有依据；标识本身不证明完成上游网络请求。
- 18:57:16 的十分钟审计向前取窗，包括切换前；不是切换后连续十分钟，也不是高并发零错误证明。
- 本轮未重跑长流、慢消费者、断连、重试或容量压力测试；带 integration build tag 的测试不能由一般单元 CI 推定执行。
