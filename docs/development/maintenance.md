# 开发历程维护规则

[返回入口](../../DEVELOPMENT_HISTORY.md) · [会话模板](TEMPLATE.md)

## 分层披露

过去开发跨越源码、发布、生产与数据库，材料散在版本说明、测试、仓库外事务及交接。2026-09-28 用户要求沉淀背景、目标、实际完成和注意事项，由 agent 判断更新时机。

1. 根 `DEVELOPMENT_HISTORY.md`：现状、约束、最近条目与待办，约 120 行以内。
2. 架构、历史页与 `entries/`：按任务展开设计和单次开发，大型功能增加独立专题。
3. 来源索引与原件：入库 JSON 保存文件名、哈希、证据级别、缺失状态；本机 `docs-local/` 与 artifacts 保存原始上传、完整输出与四角色，核验时才展开。

`docs-local/development-history/sources/` 不随普通 clone 到新机器。缺失时写“仅索引可用”，不伪造逐字证据；已入库摘要与 Git 仍能解释设计背景。

## 更新触发点

| 事件 | 更新内容 |
| --- | --- |
| 接手任务或范围变化 | 背景、目标、起点与下一动作 |
| 查明原因、选择方案、推翻推断 | 发现/取舍，必要时同步架构与索引 |
| 修改、测试、构建形成结果 | 实际完成、命令与证据；失败/未执行也保留 |
| 发布、部署、数据操作、回滚 | 独立对象、时间、输入、结果与回滚边界 |
| 阻塞或证据缺口 | 实际错误、退出码、缺失条件与下一动作 |
| 阶段结束、中断、交接、最终回复前 | 同步根索引与会话，不遗留假进行中 checkpoint |

当前任务内的记录更新无需额外询问。阶段结束前写入并用中文简短告知重要发现和记录位置，不堆流水账。“实时”指 agent 工作中的增量维护，没有后台常驻服务，停止运行后无法继续感知状态。

## 每轮最小内容

使用 `entries/YYYY-MM-DD-主题.md`，同一任务续写同一条目。统一 UTC，必要时并列原时区。

- 背景：触发问题、用户意图、来源。
- 目标：本轮范围与可观察验收事件。
- 起点：TARGET、分支、HEAD、工作树、原字节哈希、输入。
- 实际完成：文件/函数/字段、前后行为、未完成项。
- 决策与注意事项：采用/放弃原因、兼容与资源限制。
- 验证：命令、相同输入、stdout/stderr、退出码与三态行为；大量输出放原账本。
- 当前状态：完成/进行中/阻塞、下一实际动作及输入；无待执行项明确写完成。
- 证据与纠正：四角色、补充索引、旧结论修正时间与依据。

## 证据口径

| 标记 | 可证明 | 不可自动推出 |
| --- | --- | --- |
| 本轮实测 | 本轮命令、输入与结果 | 未测环境或大负载通过 |
| 本轮静态核对 | 本机源码/Git/附件字节与结构 | 测试已跑、生产使用相同字节 |
| 历史记录 | 可定位材料的当时观察 | 本轮复查、原件已本机重开 |
| 待验证/推断 | 方向、假设、缺口 | 根因或验收已确认 |

真实命令事件优先于任务文字；当前源码优先于旧注释。后续成功不抹掉之前失败，冲突时追加更正时间、依据和影响。`usage_logs` 成功用量与错误事件不是同一分母；canary、unit、带标签 integration 与生产负载分开记。源码默认不是生产配置；健康须核对端点和响应体，SPA HTML 200 不能算后端健康。

## 事务与回滚

保存 pristine bytes/哈希，在副本用同一命令和输入执行 BASELINE → MODIFIED → ROLLBACK.sh → ROLLBACK → 重施补丁。恢复字节须等于基线，候选最后仍是预期修改。新增文件的 pristine 状态为不存在，回滚删除而非置空。

四角色：修改文件或归档、重建补丁、逐字验证账本、可执行自包含回滚脚本。同事务沿用四路径并追加；新对象另建事务，不替换旧历史证据。脚本注明前提和目标参数，先在副本实际执行。

源码、生产容器/Caddy、共享数据库字段分别是事务；不能用一种回滚证明其余已撤销。旧交接命令是资料，不自动成为本次生产指令。

## 收录与完成标准

`.gitignore` 精确放行根 `AGENTS.md` 和 `docs/development/**`；根 `DEVELOPMENT_HISTORY.md` 可跟踪。原件仍被忽略，维护记录不会自动提交、推送或发布。

不入库 token、密码、Authorization/Cookie、私钥、完整请求/数据库转储。私人连接参数和账号标识只留在确需的本机原件中；脱敏重写不能冒充逐字原件。

结束前确认背景/目标/完成/注意事项齐全、链接与 JSON 可解析、身份和时间准确、原输出未改写、四角色重开且回滚实测、状态已更新。文档变更只验结构/链接/证据/回滚，不称为应用回归通过。
