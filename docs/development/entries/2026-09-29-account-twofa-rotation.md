## 实际完成

- 凭证守护增加独立 worker 地址/访问密钥，默认关闭；管理员路由支持提交、查询、继续验证与按任务 ID 读取结果。原自动重登与推理路由不触发 2FA 更换。
- 管理界面支持明确确认、批量提交、原请求 ID 重试、状态轮询、复制已验证新密钥和回写唯一匹配的既有重登配置；不更改密码、账号分组、代理或 OAuth token。
- 可选私有 worker 复用固定提交 9fa8b481a2e5252ce2782833f6d1e0623c68fdce 的 Change-2fa-Password-GPT-Auto 任务引擎，保留 MIT 许可。实际调用 HTTP 登录与 MFA 路径，仅安装相应 Python/Node 依赖，不启动上游桌面服务、bootstrap 或浏览器。
- worker 使用 bearer 鉴权、Fernet 加密密码/密钥/状态/错误、持久化幂等键与进程锁。任务上限 1000，串行执行，禁用自动重复轮换。重启将未完成任务转为待验证或人工确认。
- Docker/Compose 采用非 root、只读根目录、回环端口、资源限制与持久卷；补充独立 worker CI、离线测试与部署/恢复说明，见 [worker 文档](../../../deploy/twofa-worker/README.md)。

## 失败与纠正

- 最初名为 baseline-go.log 的 Go 运行误挂载正在编辑的候选目录，出现暂时缺失函数错误；不计作基线。随后从固定基线新建不可变 worktree。第一次筛选表达式未命中原有测试，只证明包编译，最终改为实际测试名称并重跑三态同命令验证。
- 系统 Python 缺少 ensurepip，改用隔离 --target 依赖目录。组件测试初次 mock 缺少 createI18n 导致测试装配失败，修正 partial mock 后通过。对应原日志保留，不用后续成功覆盖。
- 最初按桌面应用推测需要浏览器；固定提交的实际轮换服务使用 get_session_pure_request 与 HTTP MFA，最终镜像仅部署该执行路径，不声称支持上游所有桌面模式。

## 注意事项与恢复边界

上游先关闭旧 TOTP、再激活新 TOTP，激活返回后才保存新密钥。此非原子窗口内发生错误可能使账号 2FA 关闭或新密钥未保存；桥接层阻止盲目重试并要求人工核对，不声称能自动恢复。worker 不能处理所有验证码/邮箱验证/SSO/风控场景。

worker 的密码/密钥加密，不代表 BPS2API 原有管理员设置加密；worker token 和回写的新密钥沿用原设置存储。需要独立保管 Fernet key 和持久卷。按任务读取结果有登录验证门槛，旧任务结果不能覆盖更新的同邮箱任务。

源码回滚只能撤销本 PR 的代码，不能撤销真实账号已发生的 2FA 变更。回滚应用时需另行决定 worker 和加密数据的保留，不能删除待确认任务或丢弃数据密钥。
