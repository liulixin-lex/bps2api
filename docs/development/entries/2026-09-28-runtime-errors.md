# 2026-09-28：多轮内容、工具选择与认证错误排查

[开发历程](../../../DEVELOPMENT_HISTORY.md) · [本轮上游整合](2026-09-28-upstream-integration.md)

## 背景与范围

用户在择优合并期间报告长历史 `type=unknown`、`tool_choice auto or none only`、模型权限 403，并授权在本机线上实例进行受限请求采集。修复写入同一隔离整合候选并随本轮 merge 提交进入本地 main。本记录区分源码、离线验证和线上观察；不把源码提交等同部署。

## 已确认的线上证据

- 本机活动容器为 `sub2api-v013`，镜像标签 `0.0.13`，HTTP 接口绑定本地 8088；本轮未切换应用镜像。
- 04:55 UTC 左右的最近一小时日志统计为 192 次 403、25 次 400，另有 502/429；这是限定窗口，不是全年故障率。
- 此后最近十分钟统计中，账号 29 出现 273 次 401；脱敏上游响应明确为 `token_revoked`。旧源码仍显示账号 active/schedulable，因此客户端重试会继续命中无效凭据。该上游认证状态不能由协议转换恢复。
- 受限采集针对用户 1，不采集媒体正文。04:57 UTC 创建的任务在 05:00 UTC 停止；211 份可解析请求仅含 input_text/output_text/input_image，工具选择为 auto 或缺省，未捕获 unknown。第二次三分钟任务进行一次有历史的子任务复现，复现成功；用户暂时无法触发旧错误。两任务均于 05:15 UTC 停止/删除并核验文件清理。原始正文不进入 Git。
- 两个已报错旧会话的本地历史包含 `agent_message.content[1] = {type: encrypted_content, encrypted_content: string}`。v0.0.13 的固定诊断标签没有 encrypted_content，因此此结构会被报告为 unknown。已用同结构脱敏夹具复现；没有逐条失败请求正文，不能断言每个 unknown 都属于该类型。

## 修复决定

1. **未知内容与密文分开**：识别 encrypted_content 并给出明确的字段路径；其他未知类型只输出有限的已知字段/JSON 类型结构，不回显正文或任意类型字符串。默认不丢内容。显式启用账号 `openai_excel_bps_ignore_encrypted_content` 时，以“密文内容不可用”提示替换该部分，保留位置、相邻明文和工具参数；这是有损继续，不是解密。需要完整子任务内容时重新提供明文或新开会话。
2. **工具选择**：支持 required、明确 function/custom/namespace 和 allowed_tools 选择。选择策略与历史工具目录分离，在整批工具交付前校验必选、单工具数量、工具身份与并行约束；不能用默改 auto 消除错误。
3. **模型权限 403**：仅对精确 model_access_changed 且未输出的响应，在原切换预算内尝试其他同实际模型 BPS 账号。拒绝隐式换模型或原生通道，耗尽时保留 403/错误码，不因某模型权限缺失停用整账号。
4. **认证 401 与 BPS 429**：纳入上游失效凭据状态管理、BPS 专用限流冷却；恢复合法 Retry-After 传递。429 及模型权限切换排除原生 OAuth/API-key 和实际转发模型不同的候选，释放被排除候选已占槽位。筛选复用实际转发的别名规范化和账号映射优先级；不以调度展示名代替上游模型。
5. **取消和终态**：修复 Messages 客户端取消后追加 502；BPS failover 耗尽明确提交终态，防止再追加通用错误。保留已计量用量记录。

## 验证与限制

工具选择、显式密文替换、结构诊断和三入口 BPS 混合池/取消定向回归已经执行通过；全量结果在整合条目汇总。新行为仍须发布后才能用于线上；本轮不自动更改生产账号开关、不更新凭据、不部署候选。

没有声称所有未知内容已兼容、密文可恢复、上游模型权限或被撤销的 OAuth 已修复。后续未知内容若仍失败，优先依据安全结构诊断与受限错误捕获确定真实形态，不能全局吞掉任意未知对象。
