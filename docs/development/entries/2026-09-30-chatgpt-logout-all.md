## 用户目标与范围

用户需要新增独立操作：输入账号邮箱、密码、当前 TOTP 密钥，自动登录后，一键退出该 ChatGPT 账号在各设备上的既有会话。继续遵守全自动约束，不引入人工浏览器验证。此轮提问重点是“怎么实现”；本轮完成源码可行性核查与具体接入设计，尚未实现、推送或部署此新功能，也未发起任何真实会话撤销。

## 当前实证

- 本地 PR HEAD 为 cbf538a3，部署业务源码 b0bbeae3。继承两份未提交文档修改，保留其原字节，不擅自覆盖或混入新业务变更。
- 固定上游 session_phase.py 已提供 logout_all_sessions_with_session（约 743–1037 行）。它复用认证 Cookie，启动独立 Camoufox profile，进入 ChatGPT 的 Security 设置；必要时打开 Active sessions/Logged in devices，点击 Log out all 及确认对话框。不是简单清空本机 Cookie。
- 此函数没有接入当前 private worker 的 jobs/service API；当前业务只暴露 2FA 轮换和结果接口。后续需要新的任务类型、管理员接口和页面动作，不能仅添加按钮就宣称已可用。
- 上游存在不够可靠的成功判定：任意 URL 包含 logout/session/device 等子串的写请求得到 2xx、页面关闭、跳转登录页均可能返回成功。这些信号不能单独证明“所有会话撤销”。接入时必须限定预期来源/操作、排除遥测和单会话退出，不因浏览器关闭就报成功。
- _account_browser_launch_spec 调用全局 load_settings；当前隔离配置只在登录桥接函数内生效。接入退出流程时须把同样的临时 profile/只读运行/清理逻辑带入，不能复用默认源码目录或其他账号的浏览器目录。
- 本项目 /api/v1/auth/revoke-all-sessions 撤销的是 BPS 自身登录令牌，不是上游 ChatGPT 的设备会话；不能混用。
- 官方帮助页此次获取返回 HTTP 403，未获得可核实的当前文字。没有据此承诺具体传播时长、Codex/OAuth refresh token 或 API key 的撤销范围。

## 具体接入设计

1. 默认独立“退出所有 ChatGPT 设备”操作，复用邮箱----密码----当前2FA密钥输入和既有私有 worker 配置；明确对象是该账号的会话，不删除 BPS 用户或订阅账号。
2. 管理 API 沿用 bearer、no-store、确认字段和幂等 request_id；使用独立 session-logout 任务，避免和 2FA 的新密钥 checkpoint/结果导出混淆。
3. worker 自动登录并验证返回邮箱；登录失败即终止，不执行退出。退出和轮换共享运行互斥，避免一个操作撤销另一个正在使用的会话。
4. 使用原生网页的退出所有会话操作；先用网络写入阻断的只读/模拟探针核对实际路径和界面，再实现精确响应匹配。不得猜测未核实的私有 API 或把任意 session 响应当成成功。
5. 分开报告“登录失败”“已提交退出请求”“已确认撤销”“结果待确认”。执行会话失效是正常可能结果，不能因它断开就自动再登录再退出；响应丢失保留任务、禁止盲目重放。
6. 不把更换密码或 2FA 隐式绑定到退出动作，也不回写/清空 BPS 已保存的 OAuth token。退出登录与阻止掌握有效凭据的人重新登录不同；账号凭据更新可作为独立明确操作。

## 验收与下一实际动作

下一步实现前，先在独立、明确阻断安全设置/会话写请求的浏览器探针中核对退出入口及请求来源，不点击放行真实撤销。然后完成 worker、Go 管理接口和单独 UI，离线覆盖幂等、身份不匹配、并发互斥、取消/重启、不确定结果和敏感信息过滤，并保留源码/部署/数据库各自证据。

真实端到端会使目标账号在已登录设备上退出，需使用明确指定的测试账号和明确的会话撤销指令。用户现在要求新增功能及评估实现，不等于授权把库里所有账号立即踢下线。本轮没有请求人工登录、没有终止任何会话。OAuth/API token 撤销范围需单独验证，不能用网页退出成功推断。

## 2026-09-30 后续：用户明确要求新增菜单，进入实现

上述“仅设计、尚未编码”属于本轮实现前的历史。用户随后明确要求在凭证守护的自动更换 2FA 左侧新增“退出所有会话”按钮菜单，输入邮箱/密码/当前 2FA 后全自动退出。已按此要求编写独立 worker 任务、Go 管理接口、页面与中英文提示；尚未部署，发布结果另附。

### 已实现的边界

- 默认仍为 2FA 页，新菜单最左；两个表单切换保留输入，共用维护服务设置，退出任务独立显示。
- 新 session_logout_jobs 表位于 requests.db，密码/TOTP/Cookie/token 只在执行内存中，不持久化到退出任务。原 jobs.db 与 rotation_requests 保留。
- 幂等、全局运行互斥、登录邮箱双重核对、请求前持久化、单次退出写请求、重启不重放；异常不回显敏感信息。
- 原生按钮触发后，只允许官方限定路径下明确 logout/revoke 类写请求，要求对应请求对象的 2xx 才返回“退出请求已确认”。页面关闭、普通 session/遥测响应、跳转登录都不能证明成功。
- 当前端点匹配是受限类别识别，实际原生退出路径尚未实测确认。禁止扩展为任意 session/device URL 或根据页面关闭推断成功。

### 本轮实测与限制

阻断退出写请求的浏览器探针在登录阶段返回 LoginBootstrapError / login_failed，没有真实退出请求，未修改原任务数据库。故未获得当前原生退出接口实证，也未完成真实设备退出验收。本轮不再擅自使用库中账号撤销会话，不接入人工验证，不能宣称已解决自动登录失败。

后端 service/handler 定向 TwoFA/SessionLogout 回归通过；worker 与前端回归、构建、源码回滚、部署回滚和浏览器检查正在执行，完成后更新结果。源码事务为 docs-local/chatgpt-logout-all-20260930/，继承的文档修改已保存原字节。
