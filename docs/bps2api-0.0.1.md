## 冲突处理

- ExcelBPSImageAdmission：保留本地两阶段读取/解压与处理预算机制；增加原子更新的动态处理限制。降低限额继续计算已在途占用，已有租约缩减与释放不会被新限额阻止。
- ReadRequestBodyWithPreallocLimit：纳入上游显式限额接口，同时保留有界读取、zstd 单解码线程及窗口限制、预读正文检查；网关准入仍限制到 64 MiB。
- forwardOpenAIExcelBPS：保留本地首字/空闲/总时长超时及实际读取活动计时，同时纳入快照、429 冷却和可选 403 处理；不增加失败请求的自动重试。
- 测试采用双方的功能覆盖，并增加部署上限、设置继承、预算禁止自动增长、降低限额释放及探测录制上限的回归。

## 默认容量及升级行为

默认在途 32，处理预算 512 MiB；独立读取/解压预算默认 512 MiB（不是二者合并共用），单解码槽和默认 250 ms 有界等待。正文最大 64 MiB。最小处理预留为 8 MiB，请求结束后释放。

后台设置对新请求立即生效，但不突破 image_relay_admission 对应部署配置的内存、并发和正文硬上限。后台最大可填写 512 槽不意味着实例实际允许 512 槽。确需扩容时，先测量目标负载的 RSS、数据库和上游限制，再显式调整部署配置；不会隐式放大到 4 GiB。

未设置新增容量键的现有实例继承既有部署覆盖值；一旦管理员保存容量字段，字段成为明确配置，并与部署上限取最小值。原有图片开关和域名保持原值。BPS 403 自动关闭默认关闭。正常超载仍可能出现有依据的 503，本版不把过载伪装成成功。

## 发布与升级

- bps2api 采用独立版本 0.0.1；上游 2.8.14 是合并来源，不是本仓库的更新通道。
- 自更新、安装脚本、Compose 和镜像发布指向本仓库；二进制名和压缩包前缀 sub2api 保留以兼容既有安装服务。
- 本版没有新增数据库迁移，新增设置按需写入已有设置表。
- 从旧 2.8.x 标识的自建版本首次切换到独立 0.0.1 时，使用固定版本安装或镜像替换；语义版本比较不会把 0.0.1 判定为 2.8.x 的自动升级。首次切换后，本仓库后续版本按正常版本顺序更新。
- 升级前备份数据库、配置和旧二进制/镜像，校验 Release 校验和。先隔离验证，再逐实例替换；生产部署需单独执行和确认。
- 回滚使用之前的二进制/镜像与原配置；保存新增设置不会迁移业务数据。源码补丁与可执行回滚证据由本次交付的四份审计文件记录。
