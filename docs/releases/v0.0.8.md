# BPS2API 0.0.8

## Native Responses compatibility and bounded recovery

This release addresses protocol failures observed in production while preserving the requested model, client tool catalog, raw source bytes, and terminal response status. It does not turn provider failures into synthetic successes.

### Changes

- Accept one unambiguous custom-input wrapper (an object containing only a string input), including a direct function-style call to an exact declared custom tool. Preserve raw string contents, Unicode and escapes. Reject additional fields, arbitrary source-key guessing, nested wrappers and non-string inputs.
- Correct a native tool hallucination, such as list_skills with an empty client catalog, once before any client-visible text or tool dispatch. The undeclared tool is never forwarded or executed.
- Recover a premature upstream EOF once only before visible output. HTTP, local protocol and EOF recovery share the same one-retry budget and original request deadline. Cancellation, timeouts, already delivered tool calls, provider refusals and flushed metadata are not replayed.
- Preserve an explicit non-streaming response.incomplete response as HTTP 200 with its original partial answer, usage and incomplete_details, matching the native Responses object contract. Internal outcome tracking still marks the request incomplete. Streaming clients continue receiving response.incomplete.
- Record compact, allowlisted incomplete reasons without copying conversation metadata into error logs. Preserve timeout classification when buffered metadata is flushed.

### Compatibility scope

| Surface | Behavior |
| --- | --- |
| Function calls | Exact declared names and object arguments; existing FUNCTION and FUNCTION_CODE transports retained |
| Custom calls | Opaque raw strings; lossless single-input wrappers; existing CUSTOM marker retained |
| Tool history | Existing call IDs, namespaces and history reconstruction retained |
| Content | Existing text, reasoning/summary text aliases and validated image aliases retained |
| Streaming | Text remains incremental; native tool events are withheld until validated; terminal status preserved |
| Incomplete responses | Partial content and reason retained, never relabeled completed |
| Recovery | At most one safe regeneration before output; shared budget and cancellation handling |
| Model permissions / quota | Genuine provider 403/429 and exhausted 5xx retries remain visible |
| Hosted tools / unsupported media | No invented execution, silent content deletion or silent model replacement |
| Stateful references | BPS still requires expanded history rather than previous_response_id |

### Validation and rollout

Regression coverage exercises custom wrappers and ambiguity rejection, metadata/empty EOF recovery, no replay after text or metadata flush, exhausted recovery budgets, cancellation, empty-catalog native tool hallucinations, partial JSON/SSE responses and sanitized incomplete diagnostics. Existing BPS timeout, quota, history, image and transport suites remain release gates.

Publish an immutable image only after CI passes. Stage alongside the previous container; verify real BPS text, function, custom, history and image requests before switching the public route. Preserve old processes for in-flight streams and image tokens. Post-cutover statistics distinguish recovered attempts, final failures and old in-flight requests; a short successful observation window is not a zero-error guarantee.

### Remaining investigation

A production request was rejected at an unknown content type. Its original payload was not retained in the ordinary error table, so that type must be identified from a bounded diagnostic capture before adding a lossless mapping. Unknown binary or structured data must not be guessed into text or dropped to make a request appear successful.

References: OpenAI Responses streaming event contract and custom tool input contract; production diagnostics are kept outside the public repository.
