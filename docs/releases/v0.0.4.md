# BPS2API 0.0.4

## Protocol and reliability

- Route forced tool choices to the native channel with the original semantics.
- Preserve custom tool text supplied through exactly one of input, args or arguments; reject conflicting fields and non-string input.
- Extend lossless FUNCTION_CODE transport to an unambiguous declared cmd, command or script string. Preserve all metadata and replay history. Never evaluate or guess malformed programs.
- Allow one malformed-JSON tool-envelope correction only before any semantic output or tool dispatch. Keep the same account/model, original instructions and total deadline. Bound buffered metadata to 64 KiB. Never replay unknown tools, structured-output validation failures, ambiguous batches, arbitrary source text, or requests after output, transport interruption, cancellation, timeout, or provider failure.
- Record response.incomplete as a failed stream with its supplied reason, even when HTTP headers already report 200. Attribute local BPS protocol failures to the gateway.
- Add bounded jitter to request-scoped 503 retries while retaining explicit provider delays, retry limits and the 8-second backoff cap.
- Replace the fixed 5-second server shutdown window with server.shutdown_timeout_seconds (default 300; zero uses the default; maximum 3600). Compose defaults allow 330 seconds before forced termination.

## Production rollout

1. Back up Compose, Caddy configuration and PostgreSQL. Record the running image digest and candidate binary hash.
2. Start the candidate on a second loopback port using the same database, Redis and secrets. Check health, version, account settings and protocol canaries before directing traffic.
3. Reload Caddy to direct new requests to the candidate. Existing requests must continue on the old process. Keep an image GET/HEAD route that falls back to the old process on 404: image tokens are process-local even when disk storage is shared.
4. Keep the old process available until active requests drain and the old image relay TTL (30 minutes) expires. Do not replay POST requests in the proxy. Confirm public probes and error logs before stopping the old container.
5. Roll back by restoring the previous Caddy route while both processes remain healthy. No schema migration is introduced by this release. Database restore is not part of ordinary image rollback.

Publish source and release artifacts after production validation when following the incident deployment workflow. Keep deployment credentials, database dumps and request content out of the repository.

## Limits

Provider overload and revoked OAuth credentials remain external failures. A single schedulable account has no independent fallback capacity. Malformed responses remain explicit errors when safe bounded correction cannot recover them; validation is not relaxed to execute ambiguous code.
