# BPS2API 0.0.10

BPS image validation now accepts the Responses API original detail value. This fixes repeated local HTTP 400 errors for Codex screenshots and image tool results. Original detail and image bytes are preserved through HTTPS references, inline image relay, message history, and function/custom tool output. No image quality downgrade or model substitution is applied.

Includes the v0.0.9 tool transport and terminal stream improvements: unambiguous custom input wrappers, empty-tool-catalog correction, one shared pre-output recovery attempt, native incomplete responses, and explicit timeout termination when the retry wait exhausts the deadline.

Validation covers message and tool-output image forms, Chat-style aliases, exact signed URL preservation, relay byte identity, streaming and non-streaming gateway forwarding, and invalid detail types. Baseline and rollback reproduce the original rejection; the modified copy accepts original detail.

Rollout uses an immutable image digest and parallel containers. The release gate verifies real BPS requests using the billing client request ID, then repeats requests through the public endpoint. Prior containers remain available for active streams, image tokens, and rollback.

Provider overload, model authorization failures, and unknown unsupported content remain explicit errors. Already delivered outputs are never replayed automatically.

Reference: https://developers.openai.com/api/docs/guides/images-vision
