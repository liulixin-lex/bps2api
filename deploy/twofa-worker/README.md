# 私有账号 2FA 更换 worker

为 BPS2API「凭证守护 → 更换账号 2FA」提供可选服务，使用账号邮箱、密码、当前 TOTP 密钥，显式更换密钥后重新登录验证。仅管理自己拥有或获授权的账号。

固定引擎：`zixfelw/Change-2fa-Password-GPT-Auto`，提交 `9fa8b481a2e5252ce2782833f6d1e0623c68fdce`，MIT / Copyright (c) 2024–2026 Infinity AI Store。镜像保留上游 `/opt/change2fa/LICENSE`。桥接层调用 jobs.py / service.py 编排，并提供 Camoufox 无人值守登录与原 HTTP 轮换功能；不启动上游桌面服务或 /api/bootstrap，不引入注册或改密码功能。

这不是 OAuth token 导入器。BPS2API 原有「2FA 登录导入」与自动重登继续使用各自配置的重登服务；本 worker 不冒充重登接口，也不会改已有账号的 OAuth token。页面默认只展示 2FA 更换，原令牌巡检/自动重登/调度恢复和通知保留在“令牌守护（高级）”入口。更换成功后点击“复制更改后的账号凭据”，剪贴板格式为 邮箱----密码----新2FA密钥，密码沿用该任务原密码；仅点击复制时通过已鉴权、no-store 的结果接口读取，任务列表和普通日志不返回密码。已有成功任务重新打开页面后仍可复制，不需再次更换。

## 部署

在本目录执行 `docker compose build`。复制 `.env.example` 为 `.env`，用 `umask 077` 和 `chmod 600 .env` 限制读取。

生成两个独立值，在本机安全保存：

```bash
# TWOFA_WORKER_TOKEN
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
# TWOFA_DATA_KEY: Fernet uses a URL-safe Base64 encoded 32-byte key.
python3 -c 'import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())'
```

将随机 token 与 Fernet key 填入 `.env` 后再启动。不要把实际凭据写入镜像、Git、工单或共享日志。

```bash
docker compose up -d
curl -fsS http://127.0.0.1:18080/health
```

默认只发布宿主机回环端口。BPS2API 若直接运行于该宿主机，填写 worker 地址 `http://127.0.0.1:18080`，访问密钥填写 `TWOFA_WORKER_TOKEN`。若 BPS2API 在容器内，应将两个服务接入受控的共同 Docker 网络，通过 `http://twofa-worker:8080` 访问；容器中的 `127.0.0.1` 不是宿主机。跨机器请使用私网或经过认证的 HTTPS 反向代理，不公开映射这个端口。

- 独立 worker 地址/密钥保存在现有管理员设置中，沿用项目的设置存储权限；管理员可读取，不宣称这些设置已加密。
- worker 的任务密码、当前/新密钥、状态内敏感数据和错误内容使用 Fernet 加密；邮箱、状态与任务 ID 明文。保管密钥和完整数据卷；丢失 `TWOFA_DATA_KEY` 无法恢复已更换的密钥。
- 单进程、串行轮换；文件锁阻止多个 worker 共享同一目录。数据库仅接受本桥接层加密格式，不能挂载上游原始桌面数据库。
- 最多保留 1000 个任务，超过容量停止接收。当前版本无自动删除功能；先安全归档已验证结果和备份，再维护数据卷，不要删除仍待确认的任务。
- 所有结果和验证接口需要 bearer token；健康检查仅返回就绪布尔值。不要开启生产 debug / 请求体日志。异常响应与任务列表不包含密码、密钥或上游诊断文本。

## 使用和失败恢复

1. 保存 worker 地址和密钥。输入每行 `邮箱----密码----当前TOTP密钥`，也接受简单的竖线或旧逗号分隔。密码含分隔符时用其他格式；复杂密码可调用 JSON API。
2. 勾选账号管理/更换确认后提交。HTTP 仅提交后台任务；刷新列表观察状态。
3. 提交响应丢失时使用「沿用原任务标识继续提交」，相同 ID/凭据返回同一任务。页面关闭不会取消已接受任务；重新打开先核对列表，勿重新创建相同批次。
4. 只有已保存新密钥但登录验证失败的任务能点击「继续验证」；此操作不再更换密钥。失败状态不自动重试轮换。
5. 只有最新的同邮箱任务成功且重新登录验证通过，才允许按任务 ID 导出完整凭据或回写唯一匹配的重登凭据；回写不会添加账号、更改密码/分组/代理。
6. 服务重启时将排队、运行或中断任务转为人工确认/待验证状态，不自动重新执行。请避免在活跃轮换期间重启或升级。

**上游不可原子化的窗口：**固定版本先关闭旧 TOTP，再开新 TOTP，且仅在激活返回后持久化新密钥。在关闭/激活/保存之间发生超时或进程中断，可能留下 2FA 关闭或新密钥未保存的状态。桥接层会阻止同账号再次提交并标记人工检查，不声称能够自动恢复此窗口。应保留账号恢复方式，通过官方账号安全设置人工核对；不要为了重试而删库。源码回滚也无法撤销已发生的账号安全设置变更。

上游要求邮箱验证码、交互式挑战或 SSO 时，仍可能不能只用密码和 TOTP 完成登录。本环境已有 Camoufox 无人工登录/MFA 读取及一次用户提交的真实更换、新密钥登录验证成功记录；不能据此宣称所有账号均适用。


包含真实上游任务引擎/SQLite 加模拟登录服务、幂等提交、加密持久化、重启恢复、仅验证重试、鉴权/请求体限制与结果白名单。测试不调用真实登录或账号安全接口。

### 登录初始化与失败阶段

镜像对固定上游 session_phase.py 应用带原文件 SHA-256 校验的小补丁：验证 authorize URL 的来源和 OAuth state，并在登录初始化返回 403/429/无效页面时立即停止。被拒绝的初始化不能继续调用 authorize/continue；不轮换指纹重试已拒绝的会话，不自动解决验证码或访问挑战。桥接服务的每次登录阶段只尝试一次。

初次登录或更换前检查失败会显示“登录失败/检查失败，未更换 2FA”，附带固定、脱敏的错误码。只有明确发生在轮换前的失败，才允许用户确认后另行创建任务；已有任务不自动重试。进入轮换调用后的一切异常继续视为待核查，保存新密钥后的失败仍只允许继续验证，绝不再次轮换。

对于固定上游产生的历史记录，仅初次登录专属错误前缀且无轮换 checkpoint、无密码变更、无重试的记录作只读状态映射；不写库重分类，也不放行中断或无法判定阶段的旧任务。API 仅返回白名单错误码，不返回原错误、Cookie、访问令牌或密钥。

HTTP 403 表示当前登录初始化被拒绝；本修复不会使被上游拒绝的网络环境自动获得访问权限。需要浏览器/邮箱额外验证的账号会明确提示，不能声称所有真实账号自动登录均已通过。

Cloudflare 明确返回 cf-mitigated: challenge 时，优先于通用 HTTP 403 分类为 login_interaction_required；仍立即停止，不自动推进账号登录或更换。普通 403 继续保留 login_access_denied。用户在其他浏览器的登录状态不会由本桥接层自动共享。

## 无人值守浏览器登录

默认镜像使用 TWOFA_LOGIN_ENGINE=camoufox。浏览器由服务端代码启动，自动填写邮箱、密码和当前 TOTP，并取得同一账号的 ChatGPT 会话及 Cookie；没有人工网页登录步骤、远程桌面、浏览器控制端口或第三方验证码服务。也可显式设置 TWOFA_LOGIN_ENGINE=http 回到原请求登录，但本次环境的 HTTP authorize 会遇到浏览器验证页。

依赖固定为 camoufox 0.5.4、playwright 1.60.0，浏览器固定 official/stable/152.0.4-beta.28，与上游配套版本一致。构建先核对原 session_phase.py 哈希，再将浏览器导航和配置接到本桥接层，补足发布仓库缺失的 browser_phase 导航依赖；仅选择 Camoufox，不自动切换引擎或代理。

每次初始登录和更换后验证都创建独立临时 profile，不复用其他账号的 Cookie，结束/取消时清理。返回会话必须具有非空 token、Cookie 和匹配的账号邮箱。浏览器登录期间禁止调用 MFA 设置写入接口；真正轮换仍由原阶段保护控制。密码与 TOTP 的每个验证接口最多提交一次。仍需人工交互时明确失败，不自动执行验证码题目。

浏览器 worker 建议至少 1 GiB 内存、256 MiB /dev/shm、192 PID，compose 已配置 /tmp 和非持久化 home tmpfs。真实任务数据库和加密密钥继续保留；浏览器缓存预装在只读镜像内。不要在已有 queued/running 任务时升级。

### 关闭旧 2FA 时返回服务器错误

固定引擎的 disable_in_house 返回 5xx 时，尚未执行 enroll 或 activate，不能声称已生成新密钥，也不能仅凭错误码断言旧密钥未受影响。列表会显示白名单原因“关闭旧 2FA 接口服务器错误”，仍保持 needs_review，禁止重试轮换、继续验证和结果导出；4xx 与其他不确定错误分别提示。此映射只解释原记录，不改写数据库或放宽阶段保护。

同邮箱存在较新任务时，旧成功记录的复制/同步按钮隐藏并说明原因，与结果接口的最新任务限制一致。需要只读核验现有凭据及 MFA 状态后再判断恢复方式；HTTP 500 的上游内部原因无法仅从状态码确定。


## 退出所有 ChatGPT 会话

凭证守护菜单的最左侧新增“退出所有会话”，默认页仍是“自动更换 2FA”。输入邮箱、密码、当前 TOTP 密钥，并勾选账号授权确认后提交；此操作与密钥轮换独立，共用现有维护服务配置。

- 管理接口 GET/POST /api/v1/admin/account-ops/token-guard/session-logout；私有 worker 为 GET/POST /session-logout/jobs。提交字段为 email、password、mfa_secret、request_id、confirmed。
- 全自动登录后再次核对账号邮箱，使用独立临时浏览器配置进入原生安全设置，点击“退出所有会话”及确认。找不到明确入口、需要额外登录验证或账号不匹配时停止，不改密码或 TOTP。
- 对应操作最多放行一次受限的官方退出写请求；请求发送前保存 revoking。仅对应请求的 2xx 响应能转为 accepted（“退出请求已确认”），页面关闭、会话失效或跳回登录均不算成功。当前真实退出端点尚未实测确认；只读探针在登录阶段失败，离线覆盖不能代替真实端到端验收。
- requests.db 新增 session_logout_jobs，仅保存邮箱、任务 ID、HMAC、状态/错误码和时间。密码、TOTP、Cookie、token 不写入退出任务表，执行结束从内存对象清理；原轮换加密数据逻辑保持不变。
- 退出、轮换与验证任务运行互斥；同 request_id 幂等。发送后丢响应或中断会标记 needs_review，阻止同邮箱再次创建退出任务；不自动重放。服务重启不恢复凭据或继续执行原任务。
- 退出请求确认不代表已逐台验证设备立即退出，也不保证 SUB2API/CPA 已导入 OAuth 凭据失效。仍持有有效账号凭据的人可能再次登录。

离线完整回归使用 python -m pytest -q 本目录，包含独立退出任务、网络请求判定与模拟原生按钮/确认流程。实际会话撤销需要明确指定的测试账号；部署验收不会自行提交库中账号。
